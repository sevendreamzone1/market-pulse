# Token optimization

Use a small evidence-driven working set. Efficiency must not skip required checks, credential boundaries, or completion of the requested task.

- Start with the current request, `AGENTS.md`, and `git status --short`; choose the relevant module from [architecture](../../../docs/ARCHITECTURE.md) only if needed.
- Search targeted paths with `rg`/`rg --files`; read matching functions and immediate consumers before expanding scope.
- Load only applicable skills and documentation sections. Do not recursively read `.venv`, `.git`, caches, large instrument masters, generated snapshots or all skill bodies.
- Batch independent reads/checks, summarize long tool results, and keep dependent edits and publication steps sequential.
- Prefer a focused patch and reuse existing tests/components. Do not rewrite complete files to make small edits.
- Record completed work, pending items, file locations, verification and limitations for handoffs; omit repeated conversation history.
- Keep progress updates and final responses concise while preserving necessary evidence and uncertainty.
- Do not introduce arbitrary token budgets, stop early, or treat unsupported assumptions as facts to save context.
